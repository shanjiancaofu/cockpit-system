# V2 模块化边界

`cockpit/` 固定为 navigator、driver、voice、agent、eunomia、hawkeye、exchange、transfer、carcloud、
debugger、spider、geois、hmi、shield、upgrader、vanguard、ros 共 17 个一级业务模块，统一维护在单仓库。
旧分层说明保存在 [V1 模块化边界](reference/V1模块化边界.md)。

## 所有权与公开接口

- navigator 管进程、加载、模式、重启和故障状态，不管理 AI 请求。
- driver 持有 Camera/ISP/编码、Audio、CAN 和车辆设备；platform/ 仅封装 Linux/硬件适配。
- voice 管 KWS/VAD/ASR/TTS、对话、意图和语音指令；agent 管模型提供者、部署、推理、多模态与调度。
- eunomia 管标定算法；hawkeye 管感知；vanguard 管风险判断/预警；shield 管最终执行约束和故障保护。
- exchange 管协议、消息转换和公开基础契约，不要求所有数据流经过 exchange。
- ros 管 ROS2/Nav2 集成与消息适配；cockpit/ros/src/ 保留 colcon 包、launch 和测试节点。
- transfer 管远程传输能力；carcloud 管车云业务，carupload 是其内部上报子域。
- spider 管数据采集/汇聚和 Recording；hmi 管 Qt 与媒体；debugger 管日志/诊断；upgrader 管 OTA；geois 管地图。

允许依赖稳定公开 API、生成的 Protobuf、基础 target 和 IPC，禁止直接引用其他业务模块的私有实现。
头文件与实现在各模块的对应功能目录内组织，不设单独的接口目录层。
跨模块可用的接口头在 `scripts/dev/module_boundaries.py` 中显式列出，接口头不得传递引入私有实现。
工具和测试可显式验证内部实现，不因此将私有实现定义为公共合同。

基础接口与实现位于 `exchange/foundation/`，包括 base/build/config/
event/health/ipc/json/runtime/time。logging 接口属于公开基础契约，实现在 `debugger/logging/`。
这里不得接收暂时无归属的业务逻辑。各调用方链接需要的最小 target，不依赖全包式 exchange Runtime。

`driver/platform/` 不依赖其他项目层；设备领域代码可使用这些适配。HMI 只消费公开帧/IPC，不直接采集设备。
底盘安全约束实现属于 shield，driver 通过公开安全接口使用已有检查，不借目录迁移修改安全语义。

## 进程、ABI 与配置

17 个源码目录不是 17 个进程。只有设备独占、故障隔离、生命周期或部署边界真实需要时才进程化。
ASR adapter、帧队列、VIC、标定求解等保持普通库，不另建 Broker service 或 Supervisor。

systemd 仍只守护 Navigator，由其管理已启用 module child。模块使用 `CockpitModuleGetApi` C ABI，
头文件位于 `exchange/abi/module_api.h`，导出表位于 `exchange/abi/module.exports`。
业务入口位于各业务目录，目标装配位于 `cmake/cockpit_runtime_modules.cmake`；Navigator 不再包含业务入口实现。

ABI 版本、显式 ModuleId/RunMode 数值、mode 组合、Socket、动态库名与安装路径继续兼容。
旧 `agent` 运行标识仍指语音装配（源码归 voice）；recording/sentinel/bridge/media/calibration/watchdog
等标识不随源码目录改名。新增 ABI 枚举只能分配新值，不能调整旧成员的数值。

每个模块的关键性、重启次数/延迟及失败状态策略保持。HMI 仍监管独立 Qt 主线程进程，不把 event loop 塞入 ABI poll。
模型服务生命周期属于 agent 的公开模型提供者能力；Navigator 不管理对话状态或模型请求调度。

## 通信与构建

同线程直接调用，同进程低频用 callback/EventQueue；连续音频沿用 SPSC/Unix packet，图像沿用共享内存，
控制/状态/文本用 gRPC，不把 PCM/图片塞入 gRPC。ROS2 工作区只保存 launch、适配和测试节点，不另持业务状态。

每个模块声明独立 target 和直接依赖，不为目录对称创建机械抽象。只有两个真实调用方出现共性需求才增加通用框架。
VLA/TensorRT、Jara 上报、WebRTC/MQTT 等不因目录存在而视为已实现。

边界检查：`python3 scripts/dev/module_boundaries.py`；底层检查：`scripts/dev/lint.sh --driver-boundaries-only`。
测试/CI 会拒绝私有跨模块引用。实施与验收见 [V2 架构重组](V2架构重组.md)。
