## 2026-08-31 - 用内核 RX 时间戳封闭 CAN backlog freshness

- SocketCAN 接收从 `read()` 改为 `recvmsg()`，打开 `SO_TIMESTAMPNS` 并强制读取 `SCM_TIMESTAMPNS`；原始 kernel realtime、映射后的 receive steady time 和 dequeue steady time保存在 `SocketCanFrame`。
- kernel realtime 通过 dequeue 时的 realtime/monotonic 同步快照映射到 steady；timestamp 缺失、来自未来、ancillary 截断或无法安全映射时接收 fail closed。
- `VehicleDataService` 使用真实 kernel RX steady time驱动 `ChassisClient` freshness，链路状态的 last RX wall time也改用 kernel timestamp。
- `VcanChassisSafetyLoop` 将真实 queue age 映射到调用方 steady clock 域；0x200/0x240 到达 300 ms freshness 边界即丢弃。回归覆盖 consumer stall 350 ms 后 drain 旧帧：旧 heartbeat 不得恢复 peer，旧 fault 不得建立 ordering baseline，后续 fresh seq=200 可正常恢复。
- 该批封闭 VM 可复现的 backlog 风险；真实 can0 上仍需通过暂停 consumer、恢复 drain 和 TEC/REC/bus-off 观测完成硬件 Gate。

## 2026-08-31 - 收口 Fault ordering、STM32 reboot 与外参旋转边界

- `ChassisHeartbeatMonitor` 用 0x200 uptime 的 uint32 serial 语义区分正常 wrap 与倒退重启，输出单调 `peer_reboot_count`；该计数进入 `ChassisState`、JSON 和 gRPC。

## 2026-08-28 - Camera 双链路、Software ISP 与性能对比

### 变更内容

- Direct V4L2 的 MMAP/RG10 采集能力位于 `cockpit/drivers/v4l2`，支持 Jetson `bypass_mode=0`、`poll`、`DQBUF/QBUF`、sequence、timestamp 和 bytesused。

### 验证结果

- IMX219 Argus `nvargus://0`：1920×1080@30，30 帧 smoke 通过；此前 900 帧连续采集通过。
- IMX219 Direct V4L2 `/dev/video0`：RG10 1920×1080，300 帧 Software ISP 处理约 30 fps，队列丢帧 0、source sequence gap 0。
- Camera/LLM 定向 CTest 通过；`pre-commit`、clang-format 和 `git diff --check` 通过。

### 设计决定

- CPU + NEON 作为默认 Software ISP 基线；CUDA 只保留为性能 prototype，必须先完成图像质量对齐和 V4L2 DMABUF 集成评估。
