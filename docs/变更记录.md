# 变更记录

本文记录 cockpit-system 的每批实现改动。后续记录统一包含变更内容、设计决定和验证结果。

## 2026-07-08 - camera 稳定性、gateway health 与录包多源索引

### 变更内容

- gateway proto/gRPC 新增 `GetStatus`，返回统一 `ServiceHealth`、车辆状态新鲜度和事件计数。
- cockpit-ui 健康总览和 `cockpit-ctl status/health` 改用 gateway 原生 health，不再通过
  `GetLatestVehicleState` 推断。
- camera status 新增 `RECOVERING`、`last_error_kind`、`restart_count`、`recover_count` 和
  `last_recover_at_ms`。
- `camera-ctl` 与 `cockpit-ctl status` 输出 camera 恢复计数和错误分类。
- camera MessageBus 到 recording 的转发采样策略抽为 `CameraRecordingBridgeFilter`，并补单测覆盖。
- recording 新增 `data_files.jsonl`，proto/gRPC 新增 `AppendDataFile`，`recording-ctl` 新增
  `--file-path` 索引入口。
- smoke 在录制会话中追加 camera 文件索引，并通过 `recording-ctl --detail` 校验索引计数。

### 设计决定

- gateway 的健康语义与 `GetLatestVehicleState` 共用同一个车辆状态新鲜度阈值，避免 CLI、UI 和
  RPC 判断不一致。
- camera 错误分类使用轻量字符串 `last_error_kind`，先覆盖 invalid argument、device unavailable、
  backend unavailable 和 start failed 等原型阶段常见原因。
- `data_files.jsonl` 只记录大块数据文件索引，不保存图片、音频或视频二进制；`events.jsonl`
  继续只承载轻量事件元数据。

### 验证结果

- `bash scripts/build.sh` 通过，CTest 29/29。
- `bash scripts/run_smoke.sh` 通过，覆盖 gateway 原生 health、camera status 和 recording
  `data_files_indexed: 1`。
- `pre-commit run --files ...` 通过。

## 2026-07-08 - 录包可复盘性增强

### 变更内容

- 新增 `core/build`，由 CMake 注入 project version、build type、git commit 和 dirty 状态。
- recording manifest 增加 `config_checksum`、`git_commit`、`git_dirty`、`build_type` 和
  `binary_version`。
- recording catalog 新增 session detail 读取能力，从 `manifest.json` 重建单会话复盘信息。
- recording proto/gRPC 新增 `GetDetail`，`recording-ctl` 新增 `--detail <session-id>`。
- smoke 增加 `recording-ctl --detail` 校验，覆盖 config checksum、git commit 和 binary version。
- `项目进度总览.md` 将录包可复盘性移入已完成主线，并把下一步调整为 camera 稳定性、
  gateway 原生健康接口和录包多源索引。

### 设计决定

- 仍保持 manifest 文件为权威来源，不引入 SQLite 运行依赖。
- config checksum 使用稳定的 FNV-1a 64 位十六进制指纹，避免为 WSL 原型阶段额外引入 crypto
  依赖。
- `events.jsonl` 继续只保存轻量元数据，大块数据后续通过独立文件索引接入。

### 验证结果

- `bash scripts/build.sh` 通过，CTest 29/29。

## 2026-07-08 - UI 健康总览

### 变更内容

- cockpit-ui 新增 `ServiceHealthModel`，后台定时轮询 gateway、audio、voice、camera 和 recording。
- Qt Dashboard 右侧新增服务健康列表，展示 OK、DEGRADED、FAULTED 和 UNKNOWN 状态、摘要和错误。
- `cockpit-ui` 启动时从 `configs/config.yaml` 读取各服务 gRPC 地址，并把健康模型注入 QML。
- `项目进度总览.md` 将 UI 健康总览移入已完成主线，并把下一步调整为录包可复盘、camera 稳定性和 gateway 原生健康接口。
- `实现状态.md` 增加 UI 健康总览模块状态。

### 设计决定

- UI 健康页只走 gRPC 控制面 `GetStatus` 或轻量状态查询，不承载 PCM、图像或其他大数据。
- audio、voice、camera 和 recording 直接使用 proto 中已有 `ServiceHealth`。
- gateway 暂未提供统一 health RPC，UI 当前通过 `GetLatestVehicleState` 可达性和数据新鲜度推断健康。
- 服务不可达显示 UNKNOWN，避免 WSL 阶段只启动部分服务时误报 fault。

### 验证结果

- `bash scripts/build.sh` 通过，CTest 29/29。
- `bash scripts/run_smoke.sh` 通过。
- `timeout 6s bash scripts/run_cockpit_ui.sh --offscreen` 在提权允许本地 gRPC 绑定后成功加载 cockpit-ui，并由 timeout 结束。

## 2026-07-07 - Runtime 依赖图、camera MessageBus 接入与录包元数据

### 变更内容

- `core/runtime` 新增 `DependencyGraph`，支持 required/optional 服务依赖和 required 环检测。
- `configs/config.yaml` 新增 `runtime.dependencies`，`cockpit-ctl dependencies` 可打印当前服务依赖图。
- camera-service 接入进程内 `MessageBus`，发布 `/camera/status` 和 `/camera/frame_meta`。
- camera-service 增加 recording bridge，采样转发 frame metadata 和状态事件到 recording-service。
- camera status 增加 preview 启动时间、连续 drop、最大连续 drop、连续 source gap 等可用性指标。
- recording manifest 增加 project、schema_version、config_path 和 sources 元数据。

### 设计决定

- `runtime.dependencies` 只表达依赖关系，不负责启动进程；进程生命周期仍由 systemd/脚本管理。
- camera 帧像素继续走 shared memory，MessageBus 和 recording 只承载轻量元数据。
- frame metadata 转发给 recording-service 做采样，避免按帧率打满 gRPC 控制面。

### 验证结果

## 2026-07-07 - Runtime MessageBus、统一健康模型与多源录包事件

### 变更内容

- `core/event` 新增进程内 `MessageBus`，支持 topic 订阅、`*` 通配订阅、队列容量、drop 统计和 metrics。
- `common.proto` 新增 `ServiceHealth`，audio、camera、voice 和 recording status 均携带统一健康字段。
- recording gRPC 新增 `AppendEvent`；`recording-ctl` 新增 `--event-topic/--event-payload` 调试入口。
- camera 拍照成功后写入 `/camera/photo` 元数据事件；voice response 写入 `/voice/response` 元数据事件。
- systemd 服务补充 vehicle/gateway/audio/voice/camera/recording 依赖关系，新增 `scripts/check_health.sh`。

### 设计决定

- `MessageBus` 只用于进程内小消息，不替代 gRPC、shared memory 或 SPSC RingBuffer。
- 录包事件只保存元数据和小 JSON，不保存图片、音频、视频二进制。
- camera/voice 对 recording-service 是弱依赖：录包服务不可用时只记录 warning，不影响用户主流程。

### 验证结果

- x86_64 Debug 构建通过，CTest 28/28。

## 2026-07-04 - 相机卡帧与断连检测

### 变更内容

- `SharedFrameReader` 新增 writer 可用性检测，camera-service 退出后 UI reader 主动断开并重连。
- Qt `CameraFrameModel` 新增 1 秒 freshness 定时器，界面区分 live、stalled 和 last frame。
- `cockpit-ctl status` 输出 camera frame health、帧龄、最后序号和源端跳帧数。
- `cockpit-ctl` 不再等待离线服务变为 ready，单机诊断在部分服务离线时立即返回。
- 新增 Qt camera model 测试，并补充共享内存 writer 退出测试。

### 设计决定

- UI freshness 属于消费者观察状态，不回写 camera-service，也不改变共享内存数据布局。
- camera-service 的 2 秒 CLI 卡帧阈值与 UI 的 1 秒显示阈值分开，诊断工具更保守。
- 保留最后一帧供用户查看，但不得把旧帧标记为实时画面。

### 验证结果
