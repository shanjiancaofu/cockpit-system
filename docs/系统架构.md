# Cockpit V2 系统架构

当前代码按 17 个业务模块组织，职责以 [模块化边界](模块化边界.md) 为准。
原 V1 详细设计保存在 [V1 系统架构](reference/V1系统架构.md)，已有实现和外部通信合同继续保留。

```text
systemd → Navigator → 已启用模块进程 / 独立 Qt 进程

driver → 公开硬件数据/控制接口 → voice / hawkeye / spider / hmi
agent → 公开模型提供者接口 → voice / hawkeye 等调用方
hawkeye / driver 数据 → vanguard 风险判断 → shield 最终执行约束
transfer 远程传输能力 ↔ carcloud 车云业务

exchange/abi：稳定模块 C ABI
exchange/contracts：共享数据合同
exchange/foundation：基础接口与实现
exchange/proto：Protobuf/gRPC
ros/bridge：ROS2/Nav2 集成与消息适配
ros/src/：colcon 工作空间包、launch 与测试节点
debugger：日志/诊断；eunomia：标定；geois：地图；upgrader：OTA
```

图中表达职责和允许的数据方向，不要求所有调用经过 exchange，也不要求每个模块成为进程。
生产 Camera 继续使用 GStreamer，Native Runtime/Broker/VIC 的隔离验证和 SIGKILL 阻塞不因迁移改判。
Camera 历史性能、CAN 安全合同、语音模型提供者和 OTA 回滚规则均保留。

具体迁移映射和兼容证据见 [V2 架构重组](V2架构重组.md)，实现完成度见 [实现状态](实现状态.md)。
