# V2 架构重组

基于 `421b5df` 将原分层结构重组为 cockpit 下 17 个业务模块。这是源码所有权、公开接口和构建依赖迁移，
不代表一次实现所有模块的规划功能。

在初始 16 模块基础上独立增加 `ros`，现为 17 个一级模块。
ROS2/Nav2 Bridge 的实现归 `cockpit/ros/bridge/`；`cockpit/ros/src/` 保留 ROS2 包结构，根目录不再保留 ros2/，协议仍归 exchange/proto。

公共基础能力按本轮确认保留在 exchange 内部，不向仓库根目录增加 common，不再另增基础库模块。

```text
cockpit/exchange/
  abi/                稳定模块 C ABI
  foundation/         base/config/time/IPC/event/runtime/logging 等接口与实现
  contracts/camera/   标定数据、CameraInfo 和加载合同
  contracts/voice/    语音与模型调用共享 DTO
  proto/              原有 Protobuf/gRPC
```

各模块的头文件直接放在对应功能目录，与实现就近组织，不额外拆分接口目录树。
Logger 实现属于 debugger/logging，不使 Navigator 变成通用依赖中心。
所有跨业务 include 均指向公开头文件，公开头也不能传递引入私有头。

## 迁移映射

| 原目录/实现 | 新归属 |
| --- | --- |
| cockpit/core | exchange/foundation，日志实现归 debugger |
| cockpit/proto | exchange/proto，文件内容不变 |
| cockpit/drivers | driver/platform |
| modules/camera、audio、can、vehicle | driver 对应子域 |
| library/driver | driver 各设备子域 runtime |
| 根 agent 语音代码、modules/voice | voice |
| 根 agent/llm | agent/llm |
| modules/hawkeye | hawkeye；标定数据/加载合同分离到 exchange |
| camera-calibrator 求解/筛选 | eunomia/camera，tools 仅保留 CLI main |
| Recording | spider/recording，保留会话、索引、校验、订阅和 RPC |
| Sentinel | vanguard/sentinel，保留策略和告警编排 |
| Bridge | ros/bridge，保留平台无关与 ROS2/Nav2 适配 |
| Media | hmi/media，保留播放/控制和现有进程边界 |
| Qt/HMI Runtime | hmi/app、hmi/runtime |
| 底盘安全适配、Watchdog | shield/chassis、shield/watchdog |
| Carupload、Upgrader、Debugger | carcloud/carupload、upgrader/runtime、debugger |
| Navigator 下业务 entry | 对应业务目录 runtime/ 或子域 |

geois 当前只有职责预留；VLA/TensorRT、多 Agent 调度、Jara 上报、WebRTC/MQTT 仍按原状态待开发。
不因为目录齐全创建空进程或声称已有这些新能力。

## 兼容边界

- CockpitModuleGetApi、ABI 版本、struct 定义和导出表不变。
- Protobuf 文件内容、package/service/字段与 gRPC 入口不变。
- ModuleId/RunMode 显式数值、mode 组合、Unix Socket 和现有运行配置不变。
- 已有 target、可执行程序、`lib/cockpit/modules/*.so` 安装路径和文件名保持。
- 旧 agent 标识仍加载 voice 的语音 Runtime；其他旧 recording/sentinel/bridge/media/calibration/watchdog 标识继续有效。
- Camera/Voice/Safety 不借迁移改行为；冻结的 Camera 基线和历史失败报告未重写。

保留原 C++ namespace 和部分 agent_* 等 target 名，避免无必要的 ABI/构建接口变化。
新目录表达职责，不通过大范围改类型名来伪装功能升级。

## 检查入口

```bash
python3 scripts/dev/module_boundaries.py
scripts/dev/lint.sh --driver-boundaries-only
cmake --build _output/build/arm64-debug -j4
scripts/tests/ctest.sh --test-dir _output/build/arm64-debug --output-on-failure
```

新检查覆盖固定的 17 个目录、私有跨模块引用、公开接口泄漏、foundation 向业务依赖和 HMI 直接采集。
反例测试注入私有引用、公开头泄漏、额外模块及 HMI 采集依赖，确保违规会被拒绝。
ROS2 的独立 ament 源路径和开发脚本同步更新，可选 Sherpa 构建开关与资源路径保持原配置兼容。
