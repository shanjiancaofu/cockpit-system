# 相机 ISP 性能实测

测试日期：2026-08-29
硬件：Jetson ARM64，IMX219，`/dev/video0`，`nvargus://0`
目标：1920×1080 @ 30 FPS，300 帧或 300 次 ISP 处理
采样工具：`camera-preview-probe`、`camera-isp-cuda-benchmark`、`tegrastats`

## 各组结果

### 第一组：Direct V4L2 + CPU ISP（scalar）

执行时设置 `COCKPIT_CAMERA_DISABLE_NEON=1`，使用 `/dev/video0` 的 RG10 MMAP 输入。

```text
captured 300 frame(s) from /dev/video0 size=1920x1080 stride=7680 bytes=8294400 fps=30.011
queue_to_output_mean_ms=23.1686 p50_ms=23.0374 p95_ms=24.1882 max_ms=37.3502
isp_mean_total_ms=23.1077
process_cpu_percent=116.993 max_rss_kib=57504
queue_dropped_frames=0 source_sequence_gaps=0
```

### 第二组：Direct V4L2 + NEON

使用同一 `/dev/video0` RG10 输入，未设置 scalar override，ARM64 构建选择 `raw10_unpack_neon.cc`。

```text
captured 300 frame(s) from /dev/video0 size=1920x1080 stride=7680 bytes=8294400 fps=30.011
queue_to_output_mean_ms=16.0595 p50_ms=16.3100 p95_ms=16.8575 max_ms=23.8717
isp_mean_total_ms=16.0074
process_cpu_percent=110.467 max_rss_kib=59448
queue_dropped_frames=0 source_sequence_gaps=0
```

### 第三组：Direct V4L2 + CUDA ISP

当前 CUDA 实现是性能 prototype：读取此前 Direct V4L2 采集的单帧
`_output/runtime/v4l2-mmap-imx219-1920x1080/frame-0.raw`，重复执行 300 次
H2D → CUDA kernel → D2H。它不是 live V4L2 pipeline，因此 queue drop 和 source sequence gap 不适用，
“实际 FPS”表示单帧处理吞吐，不表示相机采集帧率。

```text
iterations=300 pixels=2073600
cuda_kernel_mean_ms=4.172
cuda_end_to_end_mean_ms=6.991
cuda_end_to_end_p50_ms=6.454
cuda_end_to_end_p95_ms=8.909
cuda_end_to_end_max_ms=9.092
process_cpu_percent=38.402
max_rss_kib=114624
```

`tegrastats` 的 `GR3D_FREQ` 采样均值为 49.95%，峰值 94%。

### 第四组：Argus + Jetson HW ISP

使用 `nvargus://0`，Argus 自动选择 IMX219 的 1920×1080、30 FPS sensor mode。

```text
captured 300 frame(s) from nvargus://0 size=1920x1080 stride=7680 bytes=8294400 fps=32.3663
process_cpu_percent=28.284 max_rss_kib=232072
```

Argus 路径当前没有公开 ISP 分阶段耗时、端到端 queue latency、queue drop 或 source sequence gap，
因此这些字段记录为 N/A，而不是用应用层帧间隔代替 ISP latency。

## 结论与限制

- Direct V4L2 + NEON 相比 scalar，在本次 300 帧实测中平均 ISP latency 从 23.108 ms 降至 16.007 ms，降低约 30.7%。
- 两条 Direct V4L2 路径均维持约 30 FPS，queue drop 和 source sequence gap 均为 0。
- CUDA prototype 的单帧端到端处理约 6.991 ms、吞吐约 143.04 次处理/s，但尚未接入 live V4L2 队列，也未完成 CPU/CUDA 颜色质量对齐，因此不作为默认 ISP backend。
- Argus 的应用层 RSS 高于 Direct V4L2；该值包含 GStreamer/Argus runtime 和驱动相关开销，不能直接等同于 ISP 算法内存。
- 本文结果是 2026-08-29 当前 Jetson/IMX219 环境的证据，后续改动或不同曝光、温度、功耗模式需要重新测量。

原始命令输出和 `tegrastats` 采样保存在本机 `_output/measurements/2026-08-29/`，该目录是构建产物，不纳入 Git。
