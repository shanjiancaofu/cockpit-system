# 自动化相机标定系统技术指导文档

## 1. 项目目标

### 1.1 项目名称

```text
camera-calibrator
```

### 1.2 V1 目标

实现一个基于 OpenCV 的 **单目相机离线自动标定系统**。

系统不是简单执行：

```text
拍 20 张照片
→ calibrateCamera()
→ 保存参数
```

而是完成：

```text
摄像头实时采集
        ↓
标定板检测
        ↓
角点质量检测
        ↓
模糊 / 曝光检测
        ↓
位置覆盖检测
        ↓
尺度覆盖检测
        ↓
重复帧检测
        ↓
自动接受候选帧
        ↓
初始粗标定
        ↓
PnP 姿态估计
        ↓
姿态覆盖指导
        ↓
最佳关键帧选择
        ↓
正式标定
        ↓
逐帧重投影误差计算
        ↓
异常帧检测
        ↓
有限次数自动重标定
        ↓
标定质量评估
        ↓
PASS / FAIL
        ↓
导出 YAML / JSON / CSV / 预览图
```

最终目标不是：

```text
“能算出 K、D”
```

而是：

```text
“能够自动判断这次标定是否可信”
```

# 4. 相机模型

普通相机采用针孔模型：

$$
s
\begin{bmatrix}
u\\
v\\
1
\end{bmatrix}
=
K
[R|t]
\begin{bmatrix}
X\\
Y\\
Z\\
1
\end{bmatrix}
$$

其中：

$$
K=
\begin{bmatrix}
f_x&0&c_x\\
0&f_y&c_y\\
0&0&1
\end{bmatrix}
$$

OpenCV 官方定义中，\(f_x,f_y\) 是像素单位焦距，\((c_x,c_y)\) 为主点；外参 \(R,t\) 表示从世界/标定板坐标系到相机坐标系的变换。

需要求出的核心内参：

```text
fx
fy
cx
cy
```

畸变参数 V1 使用：

```text
k1
k2
p1
p2
k3
```

即：

$$
D=
[k_1,k_2,p_1,p_2,k_3]
$$

OpenCV 的基础标定模型包含径向畸变和切向畸变。

# 5. 坐标系

至少理解：

```text
标定板坐标系 Board
        ↓ R,t
相机坐标系 Camera
        ↓ Perspective
归一化图像坐标
        ↓ K + distortion
像素坐标 Pixel
```

对于棋盘格：

```text
Z = 0
```

例如 square size = 25 mm：

```text
(0,   0, 0)
(25,  0, 0)
(50,  0, 0)
...
(0,  25, 0)
(25, 25, 0)
...
```

这些点叫：

```text
objectPoints
```

检测出来的：

```text
(415.27, 282.64)
(452.13, 279.91)
...
```

叫：

```text
imagePoints
```

OpenCV 官方标定流程也是利用已知 3D object points 与检测得到的 2D image points 求内外参。

# 6. 标定板设计

推荐第一版使用：

```text
9 × 6 inner corners
```

注意：

> `9 × 6` 指的是内部角点数量，不是黑白格数量。

因此真实格子：

```text
10 × 7 squares
```

推荐：

```text
square_size = 25 mm
```

棋盘本体约：

```text
250 mm × 175 mm
```

可以打印到 A4。

打印要求：

```text
打印比例：100%
禁止 Fit to Page
禁止自动缩放
使用哑光纸
贴在硬质平板
尽量保持完全平整
四周保留白边
```

打印后必须实际测量格子。

例如设计为：

```text
25.00 mm
```

实际测出来：

```text
24.82 mm
```

程序中应该填写：

```text
24.82
```

而不是 25。

棋盘平整度非常重要。纸张弯曲会让“Z=0 平面”的假设失效。

OpenCV 对现代 `findChessboardCornersSB()` 也明确建议棋盘外围保留约一个方格宽的白色边界，以改善检测稳定性。

# 7. 相机采集条件

标定过程中尽量固定：

```text
图像分辨率
裁剪方式
数字缩放
镜头焦距
对焦状态
ISP 模式
```

特别注意：

> 变焦镜头改变焦距后，原来的标定参数通常不能直接继续使用。

如果自动对焦导致实际焦点明显变化，也可能导致内参发生变化。

因此固定焦距镜头最好。

例如最终程序工作：

```text
1920 × 1080
```

就尽量直接使用：

```text
1920 × 1080
```

进行标定。

如果仅仅把完整图像等比例 resize，OpenCV 的相机矩阵参数可以相应缩放；但如果进行了 crop、ROI、数字变焦等操作，就不能简单认为参数完全等价。OpenCV 官方也指出图像缩放时内参应随缩放比例一起调整。

# 13. 棋盘检测模块

传统方法：

```cpp
cv::findChessboardCorners()
cv::cornerSubPix()
```

现代 OpenCV 可以优先尝试：

```cpp
cv::findChessboardCornersSB()
```

官方说明 `findChessboardCornersSB()` 使用 sector-based 方法，并直接返回亚像素级内部角点，在噪声和大图情况下通常更适合高精度标定。

建议 V1：

```text
优先：
findChessboardCornersSB()

Fallback：
findChessboardCorners()
+
cornerSubPix()
```

传统：

```cpp
bool found = cv::findChessboardCorners(
    gray,
    cv::Size(board.cols, board.rows),
    corners
);

if (found) {
    cv::cornerSubPix(
        gray,
        corners,
        cv::Size(11, 11),
        cv::Size(-1, -1),
        cv::TermCriteria(
            cv::TermCriteria::EPS |
            cv::TermCriteria::COUNT,
            30,
            0.001
        )
    );
}
```

OpenCV 官方基础标定流程同样使用角点检测后进行亚像素优化。

# 14. 棋盘完整性检查

必须满足：

```text
corners.size()
==
board.cols × board.rows
```

例如：

```text
9 × 6 = 54
```

不是 54：

```text
REJECT
BOARD_INCOMPLETE
```

同时要求棋盘角点不能过于接近图像边缘。

例如：

```text
margin >= 5~10 px
```

V1 不接受部分棋盘。

# 15. 棋盘面积检测

不要单纯使用 axis-aligned bounding box。

可以取：

```text
最外围角点
→ convexHull
→ contourArea
```

得到：

$$
A_{pattern}
$$

定义：

$$
ratio =
\frac{A_{pattern}}
{W\times H}
$$

这里严格来说是：

```text
inner-corner pattern footprint ratio
```

而不是完整物理棋盘面积。

推荐初始阈值：

```text
0.08 < ratio < 0.65
```

例如：

```text
ratio = 0.03
```

则：

```text
REJECT
BOARD_TOO_SMALL
```

如果：

```text
ratio = 0.78
```

则：

```text
REJECT
BOARD_TOO_LARGE
```

这些数字只是初始工程参数，应根据镜头 FOV、分辨率和棋盘大小实测调整。

# 16. 图像空间覆盖

将棋盘中心：

$$
(c_x,c_y)
$$

归一化：

$$
x_n=c_x/W
$$

$$
y_n=c_y/H
$$

然后划分 3×3：

```text
┌────┬────┬────┐
│ LT │ T  │ RT │
├────┼────┼────┤
│ L  │ C  │ R  │
├────┼────┼────┤
│ LB │ B  │ RB │
└────┴────┴────┘
```

例如：

```cpp
int col = std::min(2, int(center.x / width  * 3));
int row = std::min(2, int(center.y / height * 3));

int cell = row * 3 + col;
```

记录：

```cpp
std::array<int, 9> occupancy;
```

但：

> 只检测棋盘中心还不够。

最终最好同时统计所有角点的二维覆盖热力图。

也就是检查：

```text
是否真正观察到了图像边缘区域
```

因为：

```text
畸变在画面边缘通常更加明显
```

因此边缘区域对畸变参数估计很重要。OpenCV 官方也说明径向畸变通常越靠近图像边缘越明显。

# 17. 模糊检测

不要对整张图片检测。

优先对棋盘区域 ROI 检测。

转换：

```cpp
cv::cvtColor(frame, gray, cv::COLOR_BGR2GRAY);
```

Laplacian：

```cpp
cv::Mat lap;
cv::Laplacian(board_roi, lap, CV_64F);
```

计算：

```cpp
cv::Scalar mean, stddev;
cv::meanStdDev(lap, mean, stddev);

double blur_score =
    stddev[0] * stddev[0];
```

即：

$$
Var(\nabla^2I)
$$

值越低通常代表越模糊。

但是：

> Laplacian variance 没有通用固定阈值。

不同：

```text
分辨率
镜头
曝光
ISO
棋盘尺寸
```

都会影响数值。

可以暂时：

```text
blur_min = 100
```

作为开发起点，然后采集：

```text
50 张清晰
+
50 张故意模糊
```

重新确定阈值。

# 18. 曝光检测

对棋盘 ROI 统计：

```text
mean intensity
dark pixel ratio
bright pixel ratio
```

例如：

```text
dark:
pixel < 10

bright:
pixel > 245
```

计算：

$$
dark\_ratio=
\frac{N_{dark}}{N}
$$

$$
bright\_ratio=
\frac{N_{bright}}{N}
$$

初始配置：

```text
mean brightness:
40 ~ 215

dark ratio:
< 5%

bright ratio:
< 5%
```

超过：

```text
REJECT
UNDEREXPOSED
```

或者：

```text
REJECT
OVEREXPOSED
```

这些同样是建议起始参数，不应视作统一行业标准。

# 19. 重复帧检测

粗标定之前没有精确姿态。

因此第一阶段使用：

```text
棋盘中心
+
棋盘面积
+
角点整体变化
```

例如定义：

$$
d_c =
\sqrt{
(x_1-x_2)^2+(y_1-y_2)^2
}
$$

坐标使用归一化坐标。

尺度变化：

$$
d_s=
|\log(A_1/A_2)|
$$

还可以计算平均角点变化：

$$
d_p=
\frac{1}{N}
\sum_i
\|p_i-p'_i\|
$$

如果：

```text
center 几乎没变
area 几乎没变
corner geometry 几乎没变
```

则：

```text
REJECT
DUPLICATE_VIEW
```

不要：

```text

↓

```

```text

```

例如：

```text

```


# 22. Provisional Calibration

基础样本满足后执行第一次：

```cpp
cv::calibrateCamera()
```

OpenCV 官方接口会根据多组 object points / image points 求出相机矩阵、畸变以及每个视角对应的旋转和平移。

生成：

```text
K0
D0
```

这里只叫：

```text
provisional calibration
```

即：

```text
临时粗标定
```

不要立即作为最终结果保存。

如果：

```text
参数非法
RMS 极差
焦距不合理
```

则：

```text
继续采集
```

---

# 23. solvePnP 姿态估计

有了：

```text
K0
D0
```

以后可以：

```cpp
cv::solvePnP(
    object_points,
    image_points,
    camera_matrix,
    dist_coeffs,
    rvec,
    tvec
);
```

然后：

```cpp
cv::Rodrigues(rvec, R);
```

转换：

```text
R
→
roll
pitch
yaw
```

这里得到的是：

> 标定板相对于相机坐标系的姿态。

不是简单意义上的“相机全球姿态”。

如果要反过来求相机相对棋盘：

$$
R_{camera}=R^T
$$

$$
t_{camera}=-R^Tt
$$

```text

pitch
distance
```

```text

-30°
-20°
  0°
+20°
+30°
```

pitch：

```text
-25°
  0°
+25°
```

distance：

```text

```

```text
20.000°
```

例如：

```text
YAW_LEFT:
yaw < -15°

-10° < yaw < 10°

YAW_RIGHT:
```

# 27. 最佳关键帧选择

所有通过质量门槛的图先进入：

```text
candidate pool
```

不要全部参加正式标定。

每张图构造特征：

$$

[

\log(A),

]
$$

其中所有维度都应标准化。

例如：

```text

yaw / 40°
pitch / 40°
distance 归一化
```

# 28. 推荐关键帧算法

V1 不需要机器学习。

可以采用：

```text
Greedy Farthest Point Selection
```

第一张选择质量最好的。

以后每次选择：

> 和当前已选帧集合“最不相似”的候选帧。

定义：

$$
d_i=
\min_{j\in Selected}
\|F_i-F_j\|
$$

然后选择：

$$
i^*=\arg\max_i d_i
$$

如果还希望考虑图片质量：

$$
Score_i
=
d_i+\lambda Q_i
$$

其中：

```text
Q = blur / corner quality / exposure quality
```

这样可以防止选出来：

```text
20 张全部中央正视图
```

# 30. 重投影误差

标定结束后绝对不要只看：

```text
calibrateCamera RMS
```

逐帧：

```cpp
cv::projectPoints(
    object_points,
    rvec,
    tvec,
    camera_matrix,
    dist_coeffs,
    projected_points
);
```

OpenCV 官方同样推荐通过 `projectPoints()` 将 3D 点重新投影并与实际检测角点比较，从而评估重投影误差。

每个角点：

$$
e_{ij}
=
\|p_{ij}-\hat p_{ij}\|
$$

每张图 RMSE：

$$
E_i=
\sqrt{
\frac1N
\sum_j
e_{ij}^2
}
$$

最终：

```text
mean_error
median_error
max_error
per_view_error
```

# 45. 主程序逻辑

整体伪代码：

```cpp
while (running) {

    frame = camera.read();

    observation = detector.detect(frame);

    if (!observation.board_found) {
        show("BOARD NOT FOUND");
        continue;
    }

    quality = quality_checker.evaluate(observation);

    if (!quality.pass) {
        rejected.push_back(observation);
        show_reject_reason();
        continue;
    }

    coverage.update(observation);

    if (!provisional_ready) {

        if (!duplicate_checker.is_duplicate(observation)) {
            candidates.push_back(observation);
        }

        if (coarse_dataset_ready()) {
            provisional =
                calibrator.calibrate(candidates);

            provisional_ready =
                validator.basicCheck(provisional);
        }

        continue;
    }

    pose =
        pose_estimator.estimate(
            observation,
            provisional
        );

    observation.pose = pose;

    if (duplicate_checker.is_duplicate(observation)) {
        continue;
    }

    candidates.push_back(observation);

    coverage.updatePose(pose);

    if (dataset_complete()) {
        break;
    }
}
```

然后：

```cpp
selected =
    frame_selector.select(candidates, 25);

result =
    calibrator.calibrate(selected);

while (outlier_optimizer.canImprove(result)) {

    auto worst =
        findWorstOutlier(result);

    if (!safeToRemove(worst)) {
        break;
    }

    selected.erase(worst);

    result =
        calibrator.calibrate(selected);
}

validation =
    validator.validate(result, selected);

report_writer.write(
    result,
    validation,
    selected,
    rejected
);
```

# 54. 整个项目最重要的思想

这个项目真正重要的并不是：

```cpp
cv::calibrateCamera()
```

这一行。

而是建立完整的数据质量闭环：

```text
Good Measurement
       ↓
Good Geometric Coverage
       ↓
Good Pose Diversity
       ↓
Calibration
       ↓
Error Analysis
       ↓
Outlier Handling
       ↓
Validation
       ↓
Reliable Parameters
```

也就是说：

> 相机标定首先是一个“高质量观测数据获取问题”，然后才是一个参数优化问题。

最终系统应该做到：

```text
用户不需要知道
“下一张照片应该怎么拍”

软件自己告诉用户：

往哪里移动
往哪里倾斜
是否太近
是否太远
是否模糊
是否曝光错误
当前样本是否重复
还缺什么姿态
最终结果是否可信
```

这样才算一个完整的 **Automatic Camera Calibration System**。


### 标定

有，而且如果你想做得更像工程项目，**“自动化标定”其实比单纯会 `calibrateCamera()` 更有价值**。

相机标定自动化可以理解成：

```text
自动采图
  ↓
自动检测标定板
  ↓
自动判断图片是否合格
  ↓
自动覆盖不同姿态/位置
  ↓
自动求内参和畸变
  ↓
自动剔除坏样本
  ↓
自动重新标定
  ↓
自动生成误差报告
  ↓
自动保存参数
```

# 1. 最基础的自动化

最简单版本就是：

```text
摄像头实时画面
    ↓
检测棋盘格
    ↓
检测成功
    ↓
自动保存一帧
    ↓
收集 20~30 张
    ↓
calibrateCamera()
    ↓
保存 YAML
```

涉及：

```cpp
cv::VideoCapture
cv::findChessboardCorners
cv::cornerSubPix
cv::calibrateCamera
cv::FileStorage
```

但这种只能算“自动采集”，还不是真正工程化。

------

# 2. 真正需要自动化的是“样本质量控制”

不能检测到棋盘就保存。

否则很容易：

```text
20 张照片
全在画面中央
全是正视
距离差不多
姿态差不多
```

这种数据量很多，但约束其实很差。

所以程序需要自动判断：

### 棋盘占画面比例

例如：

```text
too small → 不保存
too large → 不保存
```

可以通过棋盘角点包围框：

ratio=AreaboardAreaimageratio = \frac{Area_{board}} {Area_{image}}

例如希望：

```text
10% < board_area < 70%
```

------

### 棋盘位置覆盖

把图像划成区域：

```text
┌────┬────┬────┐
│ LT │ T  │ RT │
├────┼────┼────┤
│ L  │ C  │ R  │
├────┼────┼────┤
│ LB │ B  │ RB │
└────┴────┴────┘
```

要求棋盘中心分别覆盖：

```text
中心
左上
右上
左下
右下
边缘
```

程序可以自动记录：

```cpp
board_center_x
board_center_y
```

然后判断当前区域是否已经采够。

这就开始像真正的“自动标定采集器”了。

------

你不希望：

```text

第2张：正面
第3张：正面
...
```

可以估计棋盘当前姿态。

例如先通过：

```cpp

```

得到：

```text

```

然后按照区间采集：

```text

-15°
  0°
+15°

  0°

```


用户移动棋盘即可。

这种叫：

> pose coverage / pose diversity

------

# 4. 自动防止重复帧

比如你手拿棋盘没动：

```text
frame 101
frame 102
frame 103
```

三张其实几乎一样。

程序应该比较：

```text
棋盘中心变化
棋盘面积变化
姿态变化
角点位置变化
```

如果：

Δpose<threshold\Delta pose < threshold

就：

```text
REJECT: duplicate pose
```

否则大量重复图片对标定帮助很小。

# 5. 自动判断图像质量

还可以检测：

### 模糊

例如 Laplacian variance：

```cpp
cv::Laplacian()
```

计算：

Var(∇2I)Var(\nabla^2 I)

太低：

```text
REJECT: blurry
```

------

### 曝光

检测平均灰度、过曝像素比例、欠曝比例：

```text
REJECT: overexposed
REJECT: underexposed
```

------

### 棋盘是否完整

角点必须全部出现。

不要允许：

```text
棋盘被截断
严重遮挡
部分角点消失
```

# 7. 自动计算每张图的重投影误差

不要只看 OpenCV 返回的 RMS。

对每张图：

```cpp
cv::projectPoints()
```

计算：

ei=1N∑j∥pij−p^ij∥e_i = \frac{1}{N} \sum_j \|p_{ij}-\hat p_{ij}\|

例如：

```text
frame 01    0.21 px
frame 02    0.18 px
frame 03    0.25 px
frame 04    1.46 px  ← 异常
frame 05    0.23 px
```

自动找 outlier。

------

# 8. 自动剔除坏帧再重新标定

这一步就比较工程化了。

流程：

```text
第一次标定
   ↓
计算每帧 reprojection error
   ↓
找到异常图片
   ↓
删除异常图片
   ↓
重新 calibrateCamera
   ↓
再次评估
```

例如：

```text
第一次：

RMS = 0.62 px

删除：
frame_07 = 1.83 px
frame_19 = 1.47 px

重新标定：

RMS = 0.29 px
```

甚至可以循环：

```text
while error > threshold:
    删除最差样本
    recalibrate
```

但注意：

> 不能无限删。

否则最后可能只剩一堆“容易拟合”的图片。

应该同时保证：

```text
样本数
空间覆盖
姿态覆盖
```

# 11.在线标定

普通方式：

```text
采集
→ 停止
→ 标定
```

进一步可以：

```text
摄像头一直运行
      ↓
持续获取观测
      ↓
不断更新相机参数
```

叫：

> online calibration

再进一步就会涉及：

```text
Camera-IMU online calibration
VIO self-calibration
SLAM self-calibration
```

这时数学和优化要求就明显高了。

你如果以后考虑视觉、机器人、自动驾驶相关岗位，我建议相机标定学习最后就以这个作为实战项目：**先单目自动标定，再扩展 Stereo、Camera-IMU 外参标定。**
