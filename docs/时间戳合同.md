# 时间戳合同

更新时间：2026-08-31。

本文固定 Camera、LiDAR、CAN 和 Odometry 的时间语义。时间戳转换必须由数据源 adapter 显式完成，
业务模块不得把 receive time、设备 uptime 或 duration 直接当成 ROS epoch。

| 时间 | 时钟域 | 用途 |
|---|---|---|
| source/sample time | 传感器或已映射 realtime | ROS `header.stamp`、跨传感器匹配 |
| received time | host realtime | 接收记录、设备时间映射 anchor、日志关联 |
| timeout time | host steady clock | watchdog、freshness、deadline、耗时 |
| log time | host wall/realtime | 人工诊断和文件时间线 |

## 数据源规则

- Camera：`source_timestamp_ns` 只有在 `source_timestamp_valid=true` 时可用；GStreamer 通过
  pipeline clock/base-time 映射到 realtime，V4L2 保留 driver clock domain 和 flags。
- LaserScan：`header.stamp` 表示该 scan 的采样时间，不能在 consumer 内重新 `now()`；真实 C1 的
  serial/driver timestamp 语义仍需硬件验收。
- CAN：SocketCAN 必须打开 `SO_TIMESTAMPNS`，用 `recvmsg()` 读取 `SCM_TIMESTAMPNS` kernel RX
  realtime，并通过 dequeue 时的 realtime/monotonic 快照映射为 host steady receive time。0x200/0x240
  freshness 只使用该映射时间，不能使用 drain/处理时的 `now()`；kernel timestamp 缺失、未来、截断或
  映射失败时 fail closed。kernel receive realtime 只用于记录。0x200 uptime 按 uint32 serial 语义
  处理：正常回绕不算 reboot，非回绕倒退才推进 `peer_reboot_count`。
- Odometry：0x181 `timestamp_ms` 是 STM32 uint32 毫秒设备时钟。`ChassisOdometryTimeMapper` 自动处理
  wrap；普通倒退按旧包 fail closed。`ChassisClient` 从 heartbeat uptime 产生单调 reboot count，
  `Ros2ChassisOdometryPublisher` 观察到 count 变化后自动 reset mapper 并重建 host realtime anchor。
  输出是 host-estimated sample time，不代表 PTP/PPS 同步；uint32 serial 的半周期歧义仍需真机 boot
  identity/运行约束确认。
- ROS Odometry：`header.stamp` 必须是映射后的 sample time；`odom→base_link` TF 必须使用同一时间。

## 跨传感器规则

- Camera/LiDAR 匹配必须比较同一 realtime/ROS time domain 的 sample timestamp。
- 超过明确 `max_timestamp_delta` 的样本 fail closed，不通过 receive time 接近来放宽。
- Camera+LiDAR 最小投影只面向 rectified image，使用 K 和显式 `T_camera_lidar`；rotation 必须满足
  `RᵀR≈I` 且 `det(R)≈+1`，点在相机后方、图像外、NaN/Inf 或时间不匹配均拒绝。
- 真机阶段必须测量 offset、drift、serial/CSI pipeline latency；VM synthetic 结果不能替代该证据。

所有 duration、timeout 和 freshness 继续使用 `steady_clock`，系统时间校准不得改变安全超时判断。
