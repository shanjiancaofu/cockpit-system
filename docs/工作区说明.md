# 本地工作区

WSL 和 Jetson 都按源码、外部资源和生成物分开。用户名及工作区根目录由机器决定，不写入脚本和
配置合同：

```text
<workspace>/
├── github/
│   ├── cockpit-system/              主项目
│   └── chassis-controller/          STM32 下位机项目（存在时）
├── models/                           可选外部模型缓存，不进入 Git
└── third_party/                      外部依赖源码或缓存，不进入主仓库
```

## 放置规则

- 项目源码和受 Git 管理的文档只放在 `github/cockpit-system`；WSL 当前示例是
  `/home/ffz/code/github/cockpit-system`，Jetson 可使用 `/home/nvidia/code/github/cockpit-system`。
- 项目构建、测试、实验和运行产物统一放在
  `github/cockpit-system/_output`。
- 根目录不允许创建 `build/` 或 `logs/`；VS Code CMake Tools 使用
  `_output/build/vscode-${buildType}`，日志使用 `_output/runtime/logs`。
- 历史根目录 `build/` 的来源是旧版 VS Code CMake Tools 配置直接调用 CMake 生成的
  `Unix Makefiles` 构建树；历史根目录 `logs/` 来自未设置 `COCKPIT_RUNTIME_DIR` 时直接运行
  `audio-probe` 或 `cockpit-navigator`，它们按开发 YAML 的相对路径写出日志。两者已迁入
  `_output`，后续由 IDE 设置、开发 YAML 和 CMake 防护共同避免复现。
- 本地生成的 WAV、测试音频和临时音频回放文件放在 `_output/runtime/fixtures/audio`；运行日志放在
  `_output/runtime/logs`，测试报告和截图放在 `_output/runtime/reports`，当前进程临时 socket 和状态
  才能放在 `_output/runtime/run`。
- 用户提供的静态媒体不进入源码或 runtime data，开发机放在 `_output/media`：manifest 在根目录，
  音乐放在 `music/`，视频放在 `video/`，导入照片放在 `imported/photos/`。相机运行时新拍照片仍放在
  `_output/runtime/data/photos`。
- 当前项目默认 AI 本地资源根为 `github/cockpit-system/_output/ai`，可用 `COCKPIT_AI_ROOT`
  覆盖。Sherpa-ONNX、ONNX Runtime、llama.cpp 和模型按固定版本放在该目录或外部受控缓存，
  不提交到主仓库，也不在程序启动时下载。Sherpa provider 源码可以留在主仓库，但
  `libsherpa-onnx-c-api.so`、`libonnxruntime.so`、模型目录和自定义关键词文件属于外部产品资源。

```text
_output/ai/
├── runtime/sherpa-onnx/v1.13.4/
├── models/kws/sherpa-onnx-kws-zipformer-zh-en-3M-2025-12-20/
├── models/vad/silero-vad/
├── models/asr/sensevoice-small-int8/
├── runtime/llama.cpp/<commit>/
├── models/llm/qwen3.5-2b-q4_k_m/
├── models/llm/qwen3.5-4b-q4_k_m/       # 可选对照，不进入默认部署
└── config/
    ├── kws-keywords-raw.txt
    └── kws-keywords.txt
```

开发媒体资源目录：

```text
_output/media/
├── manifest.yaml
├── music/
├── video/
└── imported/photos/
```
