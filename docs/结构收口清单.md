# 结构收口清单

更新时间：2026-07-12。

本文记录结构审计结论，目标是减少职责混合和无效构建层级，不追求目录数量、文件行数或 target 数量
本身。当前 `cockpit/` 与 `tools/` 下有 73 个 `CMakeLists.txt`，默认构建有 37 项 CTest；任何移动都
必须保持依赖方向、行为和验证基线。

## 保留

| 区域 | 原因 |
|---|---|
| `core/modules/drivers/services/apps/tools` 顶层分层 | 依赖方向和设备所有权清楚，没有反向业务依赖 |
| ALSA、GStreamer、Qt、gRPC、Threads 相关独立 target | 隔离了真实第三方依赖和编译条件 |
| audio/camera/voice 的领域子模块 | 有独立状态、算法或测试，不是为了目录对称 |
| recording session/catalog/timeline/integrity | 分别承担写入、目录管理、读取和校验，职责已经分离 |
| shared frame buffer 和 audio processing 大文件 | 资源布局、并发状态与生命周期高度内聚，不按行数拆散 |

## 已收口

| 区域 | 处理 |
|---|---|
| `tools/cockpit-ctl` | executable 入口缩为 `main -> ctl::Run`，命令实现集中在 `commands.cc`；没有新增 library 或类 |
| 单次薄辅助函数 | camera 设备条件、默认照片名和录包范围判断已就地表达 |
| 抽象规则 | `代码风格.md` 已明确真实调用方、复杂度边界和 review 顺序 |

## 候选

这些项目只进入后续审计，不代表必须改：

| 区域 | 需要先确认 |
|---|---|
| `core/base` INTERFACE target | 去掉 target 后是否能减少依赖且不破坏公共 include 约定 |
| audio/camera/voice 聚合 INTERFACE target | 当前测试和上层 target 是否仍依赖兼容聚合入口 |
| `audio/playback` 单接口目录 | 独立 playback 语义是否值得保留，或由实际 provider 出现后再扩展 |
| `ui_model` 聚合 target | 是否只为测试兼容存在，能否直接链接 `ui_vehicle/ui_health` |

候选项没有明确净收益时保持不动，不为减少 `CMakeLists.txt` 数量而合并。

## 后续批次

1. 审计 `system_config.cc`：保持一个 `SystemConfig` 公共入口，确认加载、字段映射和校验是否已经影响
   阅读；只有形成稳定职责后才拆文件。
2. 输出实际 target 直接依赖，清理不必要的聚合 target 依赖，不改目录外观。
3. 审计 `recording-ctl` 和 `audio-probe` 命令分派；只按真实命令边界整理，不按函数数量拆文件。
4. 合并重复状态文档，将历史设计留在参考区，当前状态只在 `实现状态.md` 和看板维护。

每批结构修改必须至少减少一项：公开符号、直接依赖、职责混合、重复逻辑或阅读跳转；不得同时增加
无关功能。完成条件固定为构建、全量 CTest、smoke、pre-commit 和对应命令行为验证。
