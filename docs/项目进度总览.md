## 当前阶段

当前处于 **WSL 开发机原型收口阶段**：先把车机端核心链路做成可编译、可测试、可诊断的单机系统。

当前不做完整云端平台，不拆前端/后端仓库，不把 Android、OTA、自动驾驶算法栈提前拉进主线。
Jetson、真实 CAN、麦克风、扬声器、CSI 摄像头和 AI 加速验证等硬件相关工作，等设备到位后推进。

## 下一步要干啥事

1. 完善录包离线报告，汇总 manifest、完整性、损坏行、时间范围和 artifact。
2. 补配置、打包和故障矩阵，收口 WSL 可自动验证边界。
3. 根据真实诊断需求实现 debugger；calibration 和硬件 watchdog 等设备到位后再接真实能力。
4. 后端协议明确后统一设计 OTA 发布签名、CA 证书链、设备身份和发布授权。

WSL 阶段只推进不依赖真实硬件、且能进入自动化验证的内容。

## WSL 后续批次

1. **录包离线报告**：基于 list/detail/timeline/verify 汇总 manifest、完整性、损坏行、时间范围和
   artifact；限制会话和 issue 数，不增加数据库，原始 JSONL 保持权威。
2. **配置、打包和故障矩阵**：覆盖字段路径、类型和范围错误，在临时根目录验证 package/install/
   healthcheck/rollback，并复现 gateway 断流、recording 不可达、队列满和 writer 重启。
3. **无硬件语音与云端**：用 mock 验证打断、连续命令、超时和 provider 失败；只有本地 broker 合同
   明确后再接 MQTT，不为尚未明确的 LLM 产品交互预建接口。

WSL 不宣称完成正式 DBC、真实声学参数、CSI/libargus、CUDA/TensorRT、Jetson systemd 权限、真实
MQTT/TLS 网络或设备时钟偏移/漂移标定。

## 当前风险

| 风险 | 影响 | 当前处理 |
|---|---|---|
| 没有 Jetson 实机 | 无法确认 ALSA、CSI、CUDA/TensorRT 和 systemd 长运行 | WSL 先完成可测结构，硬件到位后集中验证 |
| 没有正式车辆信号 | CAN codec 仍是原型 | 保持 VehicleState 抽象，等待 DBC/信号定义 |
| 预留模块尚未实现 | 调试、标定和硬件 watchdog 不能进入生产 mode | 骨架启动明确失败，完成真实生命周期后再加入 mode |
| 升级仍是开发机原型 | 无发布身份认证和真实断电恢复时不能安全用于车辆 | 当前只验证进程中断事务；PKI/CA 配合后端设计 |
| 文档持续增长 | 重复内容容易过期 | 架构、状态、看板、专题和变更记录各保留一个权威入口 |
| AI 模型性能未知 | Jetson 上可能不满足实时性 | whisper.cpp 先保留，后续再评估 sherpa-onnx/SenseVoice/Qwen ASR |

## 硬件到位后

1. Jetson 上验证 package、systemd 和日志目录。
2. 验证麦克风、扬声器、AEC、增益、播放和打断。
3. 验证 USB/CSI 摄像头 pipeline、预览、拍照和长稳。
4. 验证真实 CAN 或 vcan-to-can 迁移。
5. 测 whisper.cpp 性能，再决定是否替换 ASR provider。
