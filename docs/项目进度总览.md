# 项目进度总览

更新时间：2026-07-17。

本文是日常推进看板，只回答当前阶段、主线完成度、下一步和风险。模块级完成度见

## 当前阶段

当前已经完成 **WSL 开发机可靠性主线收口**：车机端主链路、动态运行骨架、失败留证、配置合同和
资源基线均形成自动验证证据。下一步只做可选的真实 ASR 开发机基线，或等待硬件到位后进入 Jetson
验证，不再为尚未明确的后端或硬件能力扩目录、加占位接口。

当前不做完整云端平台，不拆前端/后端仓库，不把 Android、OTA、自动驾驶算法栈提前拉进主线。
Jetson、真实 CAN、麦克风、扬声器、CSI 摄像头和 AI 加速验证等硬件相关工作，等设备到位后推进。

## 当前风险

| 风险 | 影响 | 当前处理 |
|---|---|---|
| 没有 Jetson 实机 | 无法确认 ALSA、CSI、CUDA/TensorRT 和 systemd 长运行 | WSL 先完成可测结构，硬件到位后集中验证 |
| 没有正式车辆信号 | CAN codec 仍是原型 | 保持 VehicleState 抽象，等待 DBC/信号定义 |
| 预留模块尚未实现 | 调试、标定和硬件 watchdog 不能进入生产 mode | 骨架启动明确失败，完成真实生命周期后再加入 mode |
| HMI 媒体动作尚未闭环 | 相机页面已可执行，但音乐没有播放器 owner | 保持明确失败，等 Qt/Android 媒体边界确定后接入 |
| 升级仍是开发机原型 | 无发布身份认证和实机断电证据时不能安全用于车辆 | 已补落盘顺序和启动恢复；PKI/CA 配合后端设计 |
| 文档持续增长 | 重复内容容易过期 | 架构、状态、看板、专题和变更记录各保留一个权威入口 |
| AI 模型性能未知 | Jetson 上可能不满足实时性 | whisper.cpp 先保留，后续再评估 sherpa-onnx/SenseVoice/Qwen ASR |

## 硬件到位后

1. 从最终 JetPack/L4T 目标机准备 sysroot，完成 ARM64 GCC Release 交叉构建、ELF 和发布包检查。
2. Jetson 上验证同一 package、动态库解析、systemd、健康检查、rollback 和日志目录。
3. 验证麦克风、扬声器、AEC、增益、播放和打断。
4. 验证 USB/CSI 摄像头 pipeline、预览、拍照和长稳。
5. 验证真实 CAN 或 vcan-to-can 迁移。
6. 测 whisper.cpp 性能，再决定是否替换 ASR provider。
