# 项目进度总览

更新时间：2026-07-08。

本文是日常推进看板，只回答当前阶段、主线完成度、下一步和风险。模块级完成度见
[实现状态.md](实现状态.md)，每批具体改动见 [变更记录.md](变更记录.md)。

## 当前阶段

当前处于 **WSL 开发机原型收口阶段**：先把车机端核心链路做成可编译、可测试、可诊断的单机系统。

当前不做完整云端平台，不拆前端/后端仓库，不把 Android、OTA、自动驾驶算法栈提前拉进主线。
Jetson、真实 CAN、麦克风、扬声器、CSI 摄像头和 AI 加速验证等硬件相关工作，等设备到位后推进。

## 下一步 3 件事

1. **UI 健康总览**
   - 在 Qt UI 展示 gateway、audio、voice、camera、recording 的 `ServiceHealth`。
   - 原因：服务和模块已经变多，不能只靠终端排障。

2. **录包可复盘性增强**
   - manifest 增加 git commit、build type、binary version、config checksum。
   - `recording-ctl` 增加 session detail 命令。
   - 原因：研发录包真正有价值的是事后能还原环境和数据来源。

3. **camera-service 稳定性**
   - 增加更明确的 restart/recover 状态和错误分类。
   - 补 camera MessageBus 到 recording 的细粒度测试。
   - 原因：真实 USB/CSI 摄像头最容易出现断开、无帧、卡帧。

## 当前风险

| 风险 | 影响 | 当前处理 |
|---|---|---|
| 没有 Jetson 实机 | 无法确认 ALSA、CSI、CUDA/TensorRT 和 systemd 长运行 | WSL 先完成可测结构，硬件到位后集中验证 |
| 没有正式车辆信号 | CAN codec 仍是原型 | 保持 VehicleState 抽象，等待 DBC/信号定义 |
| 服务逐渐变多 | 排障复杂度上升 | 做统一 `ServiceHealth`、cockpit-ctl 和 UI 健康页 |
| 文档持续增长 | 重复内容容易过期 | 状态、看板、架构、蓝图、变更记录分工维护 |
| AI 模型性能未知 | Jetson 上可能不满足实时性 | whisper.cpp 先保留，后续再评估 sherpa-onnx/SenseVoice/Qwen ASR |

## 硬件到位后

1. Jetson 上验证 package、systemd 和日志目录。
2. 验证麦克风、扬声器、AEC、增益、播放和打断。
3. 验证 USB/CSI 摄像头 pipeline、预览、拍照和长稳。
4. 验证真实 CAN 或 vcan-to-can 迁移。
5. 测 whisper.cpp 性能，再决定是否替换 ASR provider。
