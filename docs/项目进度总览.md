## 下一步要干啥事

按以下顺序推进：

1. ROS 2 Humble/Nav2 provider、官方 bringup 和 Ubuntu correctness 故障矩阵已完成并封板；下一步等待真实机器人几何、地图和 localization/SLAM 数据源。
2. C1 软件集成固定官方 `rplidar_ros` 精确 revision，fake/real 切换保证只有一个 `/scan` owner；下一步只做 C1 串口、scan mode、range/quality、TF 和 rosbag 真机验收，不重写雷达协议。
3. IMX219 1920×1080 内参、CameraInfo/rectify adapter、GStreamer timestamp 映射以及 Synthetic Camera→三个 ROS topic 的 publisher 测试已完成；下一步只在 Jetson Camera runtime 组装真实 publisher。
4. `/cmd_vel → Production Safety Adapter → FakeChassis` 与 vcan 0x200/0x240/0x181 RX→Safety→0x101 TX E2E 已完成；0x240 duplicate/old ordering、peer timeout/reboot baseline 和旧 fault sample fail-closed 已补齐，真实 STM32 联调前仍不打开 can0。
5. `0x181 → uint32 wrap/reboot-aware time mapper → nav_msgs/Odometry → /odom` VM topic 链路已完成；0x200 uptime 确认 reboot 后 publisher 自动 re-anchor，无证据倒退继续拒绝。host anchor、轮径、slip、机械参数和真机漂移保持 NOT HARDWARE VERIFIED。
6. Camera+2D LiDAR rectified-image 最小投影已覆盖 valid/behind/outside/invalid/time mismatch，并拒绝非正交或 reflection rotation；真实外参 YAML/binding 和同步只在 C1+Camera 真机验收。
7. VM 软件清单至此收口；硬件严格按 C1 `/scan`、IMX219 ROS runtime、Jetson↔STM32 CAN FD bench 三个独立 Gate 推进。CAN bench 通过后才实现显式 `OpenHardware("can0")` 和 Safety→can0 wheels-up；不得放宽现有 `OpenVcanOnly("vcan0")`。SR501 和红绿灯识别继续后置。

真机交接入口已固定为 `scripts/setup/jetson-preflight.sh`；VM 不模拟 ARM64、CUDA、设备节点或真实 CAN。
